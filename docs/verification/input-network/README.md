# 入力許可・操作感・Ubuntu接続設定の検証

2026-09-29、1.2.0-beta.1のローカル候補版。GitHub Issues #1、#2、#3に対応。公開済みバージョンへの反映は別途行う。

- WindowsとWSL Ubuntu 22.04で共通Python/JavaScriptチェックが成功。デスクトップのNodeテストは33成功・3 OS依存スキップ。
- Windows/LinuxのPyInstaller実行ファイルで、単独起動、新しい静的ファイルの内容一致、入力許可・ネットワーク状態API、QR生成を確認。Linuxで選んだLANの保存と接続URLへの反映を確認。詳細は同じフォルダのpackage.json記録。
- 実ブラウザの375×667と320×568で画面全体のスクロールがないことを確認。「操作感」の変更が再読み込み後も残ること、許可喪失でキーが無効になることを確認。スマホ実機での今回の変更は未確認。
- PC接続画面はテスト用データで複数LANの選択、選ぶ前のQR非表示、選択後のQR表示、編集画面への復帰を確認。スクリーンショットを保存。
- ホストと分離したUbuntu 22.04コンテナ（bridge、NET_ADMIN、ホストネットワーク不使用）で実UFWとパッケージ用ヘルパーを実行。許可の追加、重複防止、解除、手動ルールの保持、0.0.0.0/0の拒否を確認。PC本体のファイアウォールは変更していない。
- 最終debを同じ専用コンテナへ導入。依存関係を解決したうえで導入済み状態とpolkitファイルのroot所有・0644を確認し、導入済みヘルパーでUFWの同じ検証を再実行。結果はufw-deb.json。テスト後に専用コンテナを削除。
- OS認証取消はNode側のテストで確認。新しいpolkit認証ダイアログの実デスクトップ操作、実スマホからのUFW越し通信は未検証。ルール設定済みを通信成功とは表示しない。

既存の配置・画像・Chrome設定は移行不要。操作感はブラウザに、LAN選択はユーザーのデータフォルダに、UFW管理記録はroot専用の/var/lib/pocket-deckに保存する。UFWが無効な場合は自動で有効にしない。deb削除時にも承認済みの許可は残すので、必要なら削除前に解除する。
