# Ubuntuで使う

Ubuntu x64は1.1.0以降に対応します。[Releases](https://github.com/masa-dev-2000/pocket-deck/releases)からdebを取得できます。検証範囲と制限は[Linux対応記録](linux-support.md)を参照してください。

## PCアプリの導入

標準の導入形式はUbuntu x64用のdebです。Ubuntuの版やX11／Waylandを先に調べる必要はありません。アプリが入力方式と利用可能な機能を確認し、必要な許可を画面で案内します。

1. Linux対応版のReleasesから`Pocket-Deck-<version>-amd64.deb`をダウンロードします。
2. ダウンロードしたフォルダで、次のコマンドを実行します。`<version>`は実際のファイル名に置き換えてください。

   ```sh
   sudo apt install ./Pocket-Deck-<version>-amd64.deb
   ```

3. アプリ一覧から「Pocket Deck」を開きます。PythonやNode.jsの追加導入は不要です。
4. 「入力を許可」が表示される場合は押し、Ubuntuの確認画面でキー・マウス操作とクリップボードを許可します。取消した場合は入力せず、後で再試行できます。
5. PCとスマホを同じWi-Fiにつなぎ、「スマホを接続」のQRをスマホで読み取ります。
6. 「配置を編集」でボタンを登録します。入力先のPCアプリを手前にして操作してください。

スマホの画面と設定はWindows版と共通です。配置・画像・Chrome連携の設定はユーザーの設定フォルダに保存します。OSの入力許可に対応していない環境では、その理由を表示し、利用可能な編集機能だけを使えます。

## npmから導入する場合

Linux対応npm版の公開後は、Node.js 22.12以上があるPCで次のコマンドを使えます。

```sh
npm install -g --prefix "$HOME/.local" --foreground-scripts @masadev/pocket-deck
```

npmはPCアプリをダウンロードし、チェックサムを検証して、Ubuntuの導入確認を開きます。そこでOSの管理者認証を完了するとdebを導入し、アプリを起動します。認証を取消した場合や導入を確認できない場合は起動しません。npm全体をsudoで実行する方式は使いません。

`--prefix`はnpmの小さな導入コマンドの保存先です。PCアプリ本体はOSのパッケージ管理によって`/opt/Pocket Deck`へ入ります。導入後はアプリ一覧から起動でき、毎回npmを実行する必要はありません。CLIも使う場合は`$HOME/.local/bin`をPATHへ加えてください。

インストールスクリプトを禁止したnpm設定では自動導入されません。その場合は、このパッケージのスクリプトだけを許可するか、debを直接導入してください。

## 文字列と連続操作

普通の入力欄は、文字列の「貼り付け先」を「通常の入力欄」にします。GNOME TerminalなどLinuxの端末へ送る場合は「Linuxの端末」を選びます。端末向けはCtrl＋Shift＋Vを使います。連続操作の文字入力にも同じ設定があります。Windowsではどちらの設定も従来のUnicode入力を使います。

連続操作は、PCアプリが画面や貼り付けを処理する時間も必要です。アプリを開く手順や文字入力の後は「待ち時間」を追加します。まず500〜1000ms程度から調整し、負荷が高いPCでは増やしてください。「1000ms＝1秒」です。入力や画面切り替えに失敗した操作をアプリが自動で繰り返すことはありません。

## Chrome連携

PCアプリの「Chrome連携」で「連携を準備」を押します。表示された拡張フォルダを、使いたい各プロファイルの`chrome://extensions`で読み込み、拡張の画面で名前を登録します。[共通の設定手順](chrome-profiles.md)を参照してください。

GNOME Wayland上では、Chromeを別のウィンドウへ前面化する要求がOSに拒否される場合があります。切り替え結果を確認できない場合はエラーを表示します。切り替えが必要な場合の選択肢は、Chromeを`--ozone-platform=x11`で起動してXWayland経由で使う方法です。アプリが既存のChromeを終了したり、プロファイルの設定を自動変更したりはしません。

## 更新・削除

アプリは起動時に更新を確認し、「更新する」を選んだ場合だけ取得・導入します。「後で」を選ぶとそのまま使えます。debの更新ではOSの管理者認証が必要です。npmから更新する場合は、先にPocket Deckを完全終了してください。起動中のアプリを強制終了しません。

PCアプリの削除はUbuntuのパッケージ管理で行います。

```sh
sudo apt remove pocket-deck-desktop
```

配置や画像などユーザーの設定は残ります。`npm uninstall -g --prefix "$HOME/.local" @masadev/pocket-deck`はnpmの導入コマンドを削除するだけで、PCアプリ本体は削除しません。

AppImageは持ち運び用の追加形式です。環境によって起動処理がsandboxを無効化する場合があるため、その状態ではPocket Deckが起動を止めてdeb導入を案内します。OS全体のセキュリティ制限を解除する必要はありません。

## 入力許可が失効した場合

スマホにも入力許可の状態を表示します。キー・マウス・文字入力のうち利用できない操作は無効になります。スマホからOSの許可を有効にすることはできません。PCアプリで許可した後、スマホの表示が更新されます。配置の編集やページ移動は引き続き使えます。

通常の許可終了後は、PCアプリの「入力を許可」から再接続できます。保持中にOSの入力許可サービス自体が落ちた場合、画面が失効表示になってもOS側に押下状態が残ることがあります。その場合は保持を解除できたとは表示しません。

GNOMEの共有停止で回復を試せますが、マウスを保持した状態では停止ボタンをクリックできない場合も確認しています。このケースを自動復旧できるとは扱っていません。検証VMではGNOMEのportal実装を再起動すると解除されましたが、他のportal利用アプリにも影響するため、Pocket Deckがその再起動を自動実行することはありません。

## スマホごとの操作感

スマホのメニューから「操作感」を開き、カーソルとスクロールの速さを別々に調整できます。0.25～3倍で、初期値は1倍です。パッド・2本指スクロール・ホイールの連続スクロールにも適用されます。設定はそのブラウザの、その接続先に保存します。PCのIPアドレスが変わった場合や別ブラウザでは初期値になります。保存できないブラウザでは、そのタブ内だけ有効です。

## UFWでスマホから接続できない場合

PCアプリの「スマホを接続」で、接続するIPv4のLANを選びます。選んだIPでQRコードを更新します。サーバー起動・入力許可・ファイアウォールの状態は別々に表示します。許可ルールがあっても、スマホとの通信成功を意味しません。

deb版でUFWとpkexecが使える場合は「接続を許可」からOSの管理者認証へ進めます。選んだインターフェース・送信元LAN・PCのIP・8765/TCPだけを許可します。UFW全体の有効化や無効化は行いません。既存のユーザー設定も変更しません。「詳細を確認」は管理者認証でルールを調べます。「許可を解除」はPocket Deckが追加・記録したルールだけを対象にします。LANを変更した場合、以前の許可は自動で消しません。不要になった許可を選んで解除してください。

AppImage版、UFWやpkexecがない環境、IPv6・VPN・別のファイアウォールでは自動設定できません。画面に表示する手動コマンドは、選んだLANに合わせたものです。`sudo ufw status verbose`で状態を確認してください。ネットワークを変更した場合はLANを選び直します。アンインストールでは承認済みの許可を消さないため、必要なら先にアプリで解除してください。
